The test environment of KSeF (Krajowy System e-Faktur, Poland's National e-Invoicing System) has its
own version of the Taxpayer Application (Aplikacja Podatnika) at
[ap-test.ksef.mf.gov.pl/web/](https://ap-test.ksef.mf.gov.pl/web/). Documents you send there are not
invoices and have no legal effect, and you may enter only fictitious data.

Status as of 12 November 2026.

## How do TEST, DEMO and production differ?

KSeF 2.0 has three public environments. TEST is for testing integrations and gets new system
versions first. DEMO (the pre-production environment) is configured like production and is for the
final check of an integration. Production (PROD) is where you issue and receive invoices with full
legal effect.

|                      | TEST                                                                       | DEMO                                                                       | PROD                                                             |
| -------------------- | -------------------------------------------------------------------------- | -------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| Taxpayer Application | [ap-test.ksef.mf.gov.pl/web/](https://ap-test.ksef.mf.gov.pl/web/)         | [ap-demo.ksef.mf.gov.pl](https://ap-demo.ksef.mf.gov.pl/)                  | [ap.ksef.mf.gov.pl](https://ap.ksef.mf.gov.pl/)                  |
| API documentation    | [api-test.ksef.mf.gov.pl/docs/v2](https://api-test.ksef.mf.gov.pl/docs/v2) | [api-demo.ksef.mf.gov.pl/docs/v2](https://api-demo.ksef.mf.gov.pl/docs/v2) | [api.ksef.mf.gov.pl/docs/v2](https://api.ksef.mf.gov.pl/docs/v2) |
| Legal effect         | none                                                                       | none                                                                       | full legal effect                                                |
| Login                | self-signed certificate also accepted                                      | real login credentials and permissions, as in production                   | real login credentials and permissions                           |
| Accepted schemas     | FA(2), FA(3), FA_PEF (3), FA_KOR_PEF (3)                                   | FA(3), FA_PEF (3), FA_KOR_PEF (3)                                          | FA(3), FA_PEF (3), FA_KOR_PEF (3)                                |

We did not find the address of the DEMO Taxpayer Application on MF (Ministry of Finance) websites.
The site ap-demo.ksef.mf.gov.pl was up on 7 October 2026. For the test version, the MF page about
the Taxpayer Application gives ap-test.ksef.mf.gov.pl/web/. Older guides still mention
web2te-ksef.mf.gov.pl, which no longer works.

TEST also accepts the older FA(2) schema, while DEMO and production no longer do. **A file accepted
in TEST may still fail in production.**

## What can you enter in the test environment?

Enter only made-up data. The MF documentation forbids sending production invoices and real company
data to TEST and DEMO, and tells you to use random NIP numbers (Polish tax IDs) for testing.

The reason is practical: TEST accepts self-signed certificates, so many people can log in in the
context of the same company. **Data entered in TEST is not isolated and other users can see it.**
So don't enter a real client or their address. The documentation doesn't say whether or when TEST
data is deleted.

Other ways TEST differs from production:

- **Maintenance windows.** Since 1 October 2025, recurring maintenance may take place in the test
  environments between 16:00 and 18:00, and disruptions may occur then. MF announces additional
  work in its [technical notices](https://ksef.podatki.gov.pl/komunikaty-techniczne/) (as it did
  for the work on 17 and 22 June 2026).
- **UPO with a suffix.** In a UPO (Urzędowe Poświadczenie Odbioru, the official confirmation of
  receipt) from TEST, the receiving party reads "Ministerstwo Finansów - środowisko testowe (TE)"
  (Ministry of Finance, test environment), and from DEMO "Ministerstwo Finansów - środowisko
  przedprodukcyjne (TR)" (pre-production environment). In production it is just "Ministerstwo
  Finansów".
- **QR codes point to a test address.** The QR code on a test invoice leads to
  qr-test.ksef.mf.gov.pl, not to verification in production (qr.ksef.mf.gov.pl).

## How do you log in to the test environment?

In TEST, and only there, KSeF accepts a self-generated certificate instead of a qualified one. One
tool that creates such a certificate is `KSeF.Client.Tests.CertTestApp` from the official C# library
(more on it below). It is a developer tool, not something for a person who wants to issue an invoice
in the browser.

The documentation doesn't say whether you can log in to the test Taxpayer Application through
login.gov.pl (with Profil Zaufany or mObywatel, the Polish government e-ID options) or which login
methods its start screen shows. The MF manual describes logging in to the application in general,
without distinguishing environments. We cover logging in to production in our
[guide to KSeF login](/en/guides/ksef-login).

DEMO requires real login credentials and real permissions, just like production. The MF manual
calls DEMO not publicly available, while the API documentation lists it among the public
environments. MF doesn't explain whether every taxpayer can get in or whether permissions granted in
production are visible there.

## How do you practise issuing an invoice?

1. Open [ap-test.ksef.mf.gov.pl/web/](https://ap-test.ksef.mf.gov.pl/web/) and check the address in
   your browser: it should contain "ap-test".
2. Issue an invoice with a made-up buyer and amount. We walk through the form step by step in the
   [guide to your first invoice in the Taxpayer Application](/en/guides/ksef-taxpayer-app-first-invoice).
3. Download the UPO and check for the suffix "środowisko testowe (TE)" (test environment).

If you invoice from software rather than the browser, switch it to the test environment and
[send a test invoice from it](/en/guides/first-fa3-invoice). Once you have an XML file, you can
check it in the [validator](/en/validator) before sending, against the FA(3) schema that production
requires.

## How do you connect software to the test environment API?

Marek is connecting an ERP system to KSeF. The base API URL in TEST is
`https://api-test.ksef.mf.gov.pl/v2` (path `/v2`, not `/api/v2`). The official MF libraries connect
to DEMO and production through the hosts `api-demo.ksef.mf.gov.pl` and `api.ksef.mf.gov.pl` with the
same `/v2/...` paths. URLs returned by the API always point to the environment that received the
request.

You can download the TEST specification as
[openapi.json](https://api-test.ksef.mf.gov.pl/docs/v2/openapi.json), and the interactive
documentation is at [docs/v2/index.html](https://api-test.ksef.mf.gov.pl/docs/v2/index.html).

### How do you set up test data?

The `/testdata/*` endpoints prepare data for test scenarios:

- `POST /testdata/person`: a natural person with owner permissions. With `isBailiff: false` this
  corresponds to a JDG (jednoosobowa działalność gospodarcza, a Polish sole trader): the person
  logging in with a PESEL (Polish personal ID number) or NIP gets the **Owner** permission. With
  `isBailiff: true`, `EnforcementOperations` (bailiff) is added.
- `POST /testdata/subject`: a VAT group or a JST (local government unit) with subordinate units,
  followed by permissions via `POST /testdata/permissions`.
- `POST /testdata/attachment` and `/revoke`: enabling and disabling attachments.
- `POST /testdata/context/block` and `unblock`: a blocked context, where authentication fails with
  error 480.
- `PUT /testdata/certificates/{serialNumber}`: shortening a certificate's validity.
- The `/testdata/limits/*` and `/testdata/rate-limits` endpoints: changing limits, with no effect on
  production.

Some of them carry the note "Tylko na środowiskach testowych" (Only in test environments) in the
specification. The documentation doesn't define whether that includes DEMO.
`POST /testdata/rate-limits/production` works only in TEST.

### Which limits apply in TEST?

The MF documentation contradicts itself. The limits page says limits in TEST are ten times higher
than in production, while the changelog for version 2.5.0 says they were aligned with production.
In DEMO the limits are the same as in production. You can read the current values from
`GET /rate-limits`.

### What else works in the test environments?

- The `X-Test-System-Warning` header forces a system warning in the response.
- The `X-KSeF-Feature: subject-identifier-validation` header turns on checking of NIP numbers and
  internal identifiers on invoices (the documentation doesn't specify whether it also works in
  DEMO).
- New API versions reach TEST first, then DEMO and production. Version 2.9.0 went live in TEST and
  DEMO on 13 October 2026, and in production on 15 October.

MF maintains two open source libraries:
[ksef-client-csharp](https://github.com/CIRFMF/ksef-client-csharp) (C#) and
[ksef-client-java](https://github.com/CIRFMF/ksef-client-java) (Java). Both connect to TEST by
default, and you select DEMO or production in the configuration. CertTestApp from the C# library
requires the .NET 10 SDK and generates a random NIP by default.
